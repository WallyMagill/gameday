## Goal

One grammar that is composed at every size and in every season: a **ranked board**
of everything live, with a hero that answers "who's winning, how long is left, what
just happened, is this the game to watch" without reading, and a `:tv` presentation
mode plus a scoped scoring takeover that gives the app a frame worth sharing.
Visual design C → A; UX B+ → A; themes become identities.

## Decisions

Recorded as directions — reasoning, and what reopens them.

- **Direction: A′ is the board** — one ranked list, no bordered tiles, no sidebar,
  no logo zone. Reasoning: the review's structural defects (equal 2×2 with no
  ranking, 8-hue color budget, a logo zone that never worked, undesigned
  empty/final/upcoming states, 62%-empty first boot) all come from the tile
  grammar; the 80×24 layout — the one frame everyone praised — is already a list.
  Reopens on live-data evidence that the list loses something the tiles had.
- **Direction: hero digits in team color, board body amber/grey** (4/4 seats after
  rebuttal). Reasoning: D's KC-red/BUF-blue frame was the strongest image in the
  set and the cheaper branch — `render_digits` already paints team color through
  the luminance floor. Reopens if two same-hue teams (SEA/BOS teal) prove
  unreadable after the floor + hue-separation rule below.
- **Direction: three declared tiers below the hero, two ink states for the hot
  mark.** Reasoning: four amber shades were undecodable at 80×24; three row
  heights carry rank, the mark carries only hot/not. Reopens never (it is the
  minimum that reads).
- **Direction: `MY GAMES` band that never re-sorts, then watchability with
  event-gated re-sort and `↑n` nudges, `s`/`:sort` to change key.** Reasoning: a
  board that reshuffles under your eyes reads as broken; pins are stable by
  construction. Reopens if users ask for a fully static mode (`:sort time`
  already gives one).
- **Direction: records off the board except dim on the hero nameplate.**
  Reasoning: `SEA 64-73` beside a giant `8` was misread as a second score by two
  reviewers. Reopens never.
- **Direction: ticker only when the list truncates (rows < 24).** Reasoning: at
  120×40 the list already shows every game; the ticker repeated the board.
- **Direction: the scoring cut is scoped** (Walter, 3–1 panel): full-screen
  takeover only when a pinned/favorite team scores; a 2-row band at the top of
  the list for anyone else; in `:tv` every scoring play takes the screen.
  Reasoning: the takeover is the asset; scoping keeps a stranger from ever seeing
  one unasked. Reopens if band-only proves enough.
- **Direction: header chips as filter state + inline league column when the list
  is mixed** (Walter, 3–1 panel). Reasoning: chips carry filter state the column
  can't. Reopens if the no-chips frame reads better once real.
- **Direction: `:tv` is the same list with the hero scaled up and the rest
  collapsed to a bottom strip — one widget, two budgets, never a second grammar.**
  Reasoning: engineer seat, unanimous after rebuttal. TV digits ship at
  `PixelSize::Full` (8 rows); a hand-rolled 5× glyph set only if the GIF demands
  it.
- **Direction: the cut renders from the same `Game`/`Play` the board renders —
  never a second formatter.** Reasoning: the D mockup printed `SEATTLE 0 BOSTON 7`
  under a home run while the digits said 8. Hard rule; a test enforces it.
- **Direction: TV mode key is `v` and `:tv`; `t` stays FAVORITE.** Reasoning: the
  mockup's `t tv` collides with the existing binding. Reopens never.
- **Direction: theme set A (decided 2026-09-02)** — ship `broadcast` (default), `studio`, `gruvbox`; rebuild
  `ceefax` and `phosphor` as real modes in sub-project 4 or drop them; retire the
  six tint themes (`nord`, `catppuccin-mocha`, `rose-pine`, `everforest`,
  `dracula`, `tokyo-night`) from the built-in list — their TOML files stay in
  `assets/themes/` and still load from `~/.config/gameday/themes/` for anyone who
  wants them. Reasoning: the design critic showed them to be one theme with six
  names; shipping them files the app under "another rice". Reopens if users ask.
- **Direction: logos are hero-only, 16×10, with the color-block fallback
  (decided 2026-09-02 by eye from the logo study, docs/research/v3-identity/
  logo-study/).** The marks flank the hero nameplates in the band's two
  29-column outer margins — no digit moves; a team without art gets the A′
  color-block+abbr identity, so the fallback degrades per-team, never
  asymmetrically. TV, the cut, and every row tier stay logo-free (the study's
  TV frames show two 40-col marks collapse the digits from 15 rows to 6 and
  evict the play feed). The existing 38 marks are regenerated at 16×10 via
  `tools/gen-logos.sh` (~100 KB); `logo.rs` slims to hero use. Coverage
  (38/~687 teams today) expands per-league inside sub-project 3 as each league
  gets its data pass — numeric-id URL table for soccer, `ncaa/500/{id}` for
  college, never a bulk scrape in this sub-project. Reasoning: at 16×10 an
  arrowhead is finally an arrowhead and the hero has the room for free; the
  brighten step cannot fix navy-on-black but the fallback path guarantees
  4.5:1 for every team. Reopens if the hero reads cluttered on a live night.

## 1. Board anatomy

Everything below is the 120×40 frame; §4 says how each part degrades.

**Header (1 row).** ` GAMEDAY ` wordmark · league chips (`ALL MLB NFL EPL`; the lit
chip is the active filter/tab; dim otherwise; only enabled leagues that have games
today appear as chips, the rest are reachable by `:league`) · right side:
`s SORT: WATCH` · `NetStatus` chip (sub-project 1) · date · clock. The right side
is laid out first; chips shed brackets, then the wordmark shortens to `GD`, before
the clock is ever clipped.

**MY GAMES band (0–N rows).** Present only when the user has pins or favorites
with a game today. Thin labeled rule `MY GAMES ─── 2 PINNED · NEVER RE-SORTS`.
Rows are drawn at the tier their watchability would earn *inside the band*
(the hero can be a pinned game; a pinned LATER game is one dim line), but the
band's order is pin order then favorite order and never changes during a
session. Pinned team abbrs take team color (the only team color outside the
hero digits).

**Hero (10 rows at 120×40).** The most watchable game on the board (or the top
of MY GAMES when a pinned game is live — pins win the hero). Layout, mirror-
symmetric: away nameplate top-left (`KC 2-0`, record dim), home nameplate
top-right; away digits left, home digits right in **team color**, 8-row
`PixelSize::Full` at ≥100 cols, sextant 4×3 otherwise; between the digits, the
clock line (`Q4 1:52`) and a state chip (`RED ZONE`, `2-MIN`, `TYING RUN ON 3RD`,
`BASES LOADED`, `POWER PLAY`, `STOPPAGE`, or nothing) — the chip is the only
filled-background element in the hero; under the digits one **fragment line**
(`2ND & GOAL · BALL ON 4 · KC BALL`; MLB uses the diamond row as its fragment
line — `OUTS ●●○ ◇◆◇ COUNT 1-0` — never both); the **meter** (field bar with
yard ticks below it; diamond; lead bar; penalty countdown) one row; the last
play `▸ Mahomes scrambles for 9, first and goal` one row. The hero has no
border; a single dim rule closes it.

**Tier 1 — promoted (≤3 rows × 3 lines).** The next most watchable live games.
Each row: 2-cell hot mark column (`▌` in `hot` when the game's state chip is
non-empty or the leverage is in the top band; dim otherwise) · 2-cell nudge
gutter (`↑2` for 10 s after an event-gated re-sort moved the row up; blank
otherwise; always reserved so rows never shift) · away abbr + league tag below ·
away score in **3-row sextant digits, amber** · home abbr · home score · clock
column (`Q4 0:48` + state word `2-MIN` in `hot`) · situation fragments · last
play line. No team color.

**Tier 2 — live, single line.** `▌ GB 13 CHI 10 Q3 4:20 NFL GB 3RD & 2 AT CHI 41`
— hot mark, abbr, score (bold), abbr, score, clock/period, inline league tag
**only when the list is mixed**, situation fragment. As many as fit.

**Tier 3 — FINAL and LATER, dim single lines** under their own labeled rules.
FINAL: `· ARS 3 BHA 0 FT EPL Ødegaard 2 assists` (a final's headline is its last
scoring play's text, or the leader's line). LATER: `· TB @ ATL 4:25 PM NFL FOX
TB -1.5 O/U 47.5` — local time from `text::fmt_start`, broadcast, odds dim. These
sections shrink first when rows run out (§4).

**Footer (1 row).** Key legend, always: `↑↓ move  enter zoom  space pin
/ filter  s sort  v tv  ? help  q quit` on the left, `upd 10s` (or the
NetStatus label) on the right; toasts and prompts own the row as today.

**Selection.** `j/k` move a single highlight through MY GAMES → hero → tiers →
FINAL → LATER as one list; the selected row gets the `▸` in its gutter and its
text in `bright`. No pages: the list scrolls, keeping the selection on screen;
the hero scrolls away with the rest. `enter`/`z` zooms the selection.

**Ticker.** Gone at ≥24 rows. When rows < 24 the list truncates, and one
`SCORES` lane above the footer carries the off-screen games (`2 OFF-SCREEN ·
2 FINAL · 4 LATER` when nothing live is off-screen).

## 2. Watchability and ordering

`pub fn watchability(g: &Game, now: OffsetDateTime) -> Watch { score: u32, hot: bool, chip: Option<&'static str> }`
in a new `src/rank.rs`, pure, tested per league with string fixtures for
`period`/`clock`:

- Not live → `score 0`, never tier 1 (finals/later are tier 3 regardless).
- Lateness `L ∈ 0..=100` from the sport's own clock grammar (`Q4 1:52` →
  late; `BOT 9TH` → late; `78'` → late; `2ND HALF` + clock; unparsed period →
  `L = 0` and a stderr line naming the string — an unparsed game can never be
  tier 1 (engineer seat's risk).
- Closeness `C ∈ 0..=100` from the margin scaled per sport (football 8 pts =
  one score; basketball 10; hockey/soccer 1; baseball 3).
- State bonuses set `hot = true` and the chip: football red zone (+40), two-
  minute warning window (+30), 4th down in opponent territory (+15); baseball
  bases loaded (+30), tying/go-ahead run on base in the 8th or later (+40, chip
  `TYING RUN ON 3RD` names the base); hockey power play (+25; from sub-project 3
  when the meter exists), pulled goalie (+40); basketball last 2 min within one
  possession (+40); soccer stoppage time within one goal (+30), red card (+10).
- `score = L × C / 100 + bonuses`; pins add nothing (they have their own band).

**Re-sort is event-gated.** The order recomputes only when a game's score
changes, its `hot` flips, its status changes, or a game enters/leaves the board.
Between events the order is frozen even though `L` keeps rising. A row that
moves up gets `↑n` in its nudge gutter for 10 s (`NUDGE_TICKS = 100` at the
live cadence); a row that moves down gets nothing. `s` cycles `WATCH → TIME
(start time, then league) → LEAGUE (enabled_tabs order, then time)`; `:sort
watch|time|league` sets it directly; the header names the active key; the
choice persists in config as `sort = "watch"`.

**Hero selection.** Top of MY GAMES if any pinned/favorite game is live, else the
highest `score`. The hero changes only on an event, never on a timer, and never
while a `:`/`/` prompt is open.

## 3. Cut overlay and `:tv`

`src/views/cut.rs`. Fires from `apply_boards` when a game gains a scoring play
(sub-project 1's delta path), rendered over `views::draw` output like `draw_help`,
timed by `until_tick` like `alerts.rs`:

- **Full-screen takeover** (3 s, `CUT_TICKS = 30`) when the scoring team is a
  favorite or the game is pinned, or when `:tv` is on. The header row survives;
  everything from row 1 down is cleared; a `▲ SCORING PLAY · KC` chip, the
  scoring word in chunky 6-row block letters (`TOUCHDOWN`, `HOME RUN`, `GOAL`,
  `BUCKET`, `FIELD GOAL`, `SAFETY`; `theme::scoring_word` extended), the hero's
  `score_block()` in team color underneath (same function, same `Game`), one
  detail line from the `Play` (`P. MAHOMES · 4 YD RUSH · Q4 1:52`), the dimmed
  bottom strip. Bell rings once (existing `bell_pending`).
- **Band** (1.5 s, `BAND_TICKS = 15`) otherwise: two rows inserted at the top
  of the list, `hot` background: `▲ HOME RUN · TEX Seager (32) · ATH 0 TEX 5`.
- Suppressed entirely while a `:`/`/` prompt is open, while help is open, and for
  the first 30 s after start (scoring plays that arrive with the first payload
  are history, not news).
- **Hard rule:** the cut takes `&Game` and `&Play` and calls the same
  `score_block`/`nameplate` functions the hero uses. A test renders a board and a
  cut for the same `Game` and asserts the score digits' cells are identical.

`:tv` / `v`: the hero grows to the full body (digits `PixelSize::Full`, linescore
row added, meter, last three plays); every other live game becomes one line in
an `ALSO LIVE — n games` strip at the bottom with its hot mark; auto-cuts to the
new top game on an event (`next cut: CHW 2 HOU 3` shown bottom-right when the
ranking says the hero should change; the cut happens at the next event, not on a
timer); `space` locks the current game (no auto-cut until unlocked); `n` next;
`Esc`/`v` back to the board. Selection and `j/k` are inert in TV.

## 4. Sizes

| Size | Hero | Tier 1 | Ticker | Notes |
|---|---|---|---|---|
| ≥120×40 | 8-row Full digits, 10 rows | up to 3 | none | reference frame |
| 100–119 cols | 8-row Full digits | up to 2 | none | |
| 80×24 | sextant digits, 6 rows total | 0 (all tier 2) | SCORES lane when truncated | `A-prime/tonight-80x24.png` |
| 60–79 cols | sextant digits, compact fragments | 0 | lane | identity holds |
| < 60 cols | hero becomes a 2-line compact row with the state chip; no digits | 0 | lane | still one list |
| < 40 cols or < 12 rows | `need 40×12, have W×H` (both numbers, correct noun) | | | |

Rows run out from the bottom: LATER shrinks to a count line (`LATER · 4 games ·
first 4:25 PM`), then FINAL, then tier 2 truncates (the lane appears), then tier
1 demotes to tier 2, and the hero is the last thing to shrink. Resize is a
re-layout from the same ranked list; nothing is cached per size.

## 5. Zoom

The zoom view becomes hero + linescore + matchup + feed: the hero block full-width
(same function), a linescore table (`1 2 3 … R H E` for MLB; quarters/periods
otherwise), the matchup line for baseball (`P: G. Kirby (6.1 IP, 2 ER) · AB:
R. Devers (1-3) · DUE UP …`), timeouts/possession for football, then the
existing PLAYS / STATS tabs. Every string comes from sub-project 1's fields; no
new data. `SCORING` shows `game.scoring_plays`.

## 6. Themes

A theme is roles, not tints. `Theme` gains `roles`:

```toml
[roles]
ground  = "bg"      # the black
ink     = "fg"      # body text
dim     = "muted"   # tier 3, rules, labels
digits  = "star"    # amber — every score outside the hero
hot     = "live"    # the hot mark, state chips, cut band, scoring word
cool    = "border"  # structure: rules, legend keys
team    = "hero"    # where team color is allowed: "hero" | "hero+marks" | "never"
```

Built-ins map their existing palettes onto these roles; `[discipline]` keys are
read for compatibility and ignored with one stderr line. The identity floor is
now two hues + team-on-hero: the design critic's "one warm per live card"
becomes enforceable. User theme files keep working. Team colors pass the
existing `ART_FLOOR` lift **and** a hue-separation rule: when both hero teams'
lifted colors are within 20° of hue and 15% of luminance, the home side is
drawn in `digits` amber and its nameplate says so with a one-cell team block.

The theme picker keeps its live preview. Theme set per the pending decision
above.

## 7. What is deleted

the tile logo *zone* (the abbr + team-color block is the row identity;
`src/tiles/logo.rs` survives slimmed for the hero's 16×10 marks and
`assets/logos/**` is regenerated at that size); `src/tiles/packer.rs` (the list layout is a top-down y-cursor —
"as many 3-row rows as fit" is not expressible in percentage constraints); every
`Block::borders` in `tiles/mod.rs`; `views/board.rs::draw_sidebar` and
`draw_slate` (FINAL/LATER are tiers); `MOMENTUM`; `n`/`p` paging and
`page`/`page_count`; layout keys `1/2/4/s` and `LayoutPref` (`layout =` in an
existing config is ignored with a note; `s` is now sort); `ScoreStyle`
(`score_style =` ignored likewise — digits are decided by tier and size); the
`GLOBAL ALERTS` / `TOP PLAYS` / `RECORDS` rails (scoring lives in the cut, the
hero's last-play line, and zoom). `render_tile` survives only as the hero and
row renderers in a renamed `src/board/` module: `hero.rs`, `rows.rs`,
`layout.rs`, `cut.rs`, `rank.rs`.
